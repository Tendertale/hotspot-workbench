## 2. 当前业务定位与流程

### 2.1 当前定位

系统当前是一个单机优先的“热点线索研判工作台”，主要完成以下闭环：

1. 录入或接收热点线索；
2. 在服务端完成关键词、平台、状态和时间范围筛选；
3. 先使用本地规则分析，再按需调用 DeepSeek；
4. 由工作人员修改、确认分析结果；
5. 将线索推进到跟踪或归档状态；
6. 通过统计卡片和事件审计观察处理结果。

当前的“自动分析”是辅助决策，不等同于自动对外发布。只有人工确认后的分析结果才会写入正式分析状态；规则与模型结论不一致、存在风险或关键信息缺失时，不允许自动进入可采纳候选状态。

### 2.2 已实现的业务路径

```text
录入热点线索
    -> 服务端过滤 / 去重 / 版本控制
    -> 本地规则分析
    -> 可选 DeepSeek 分析
    -> 人工编辑与确认
    -> 进入跟踪
    -> 归档
    -> 统计与审计事件
```

线索通过标准化后的来源 URL 进行重复检测；同一个来源 URL 的重复录入会返回冲突，而不是静默创建两条业务数据。

### 3.2 规则分析、数据库与审计

`backend/app/analyzer.py` 已形成可独立测试的本地规则分析逻辑，包含：

- 热点分类；
- 风险词识别；
- 来源和时间信息检查；
- 过期时间、未来时间和无效互动量识别；
- 置信度计算；
- 自动候选边界判断。

`backend/app/database.py` 已形成 SQLite 持久化层，包含：

- `hotspots`：热点线索主体；
- `hotspot_analyses`：分析结果；
- `hotspot_events`：业务事件审计；
- 版本字段和更新声明机制；
- 标准化来源键 `source_key`；
- 列表筛选、分页和统计查询；
- 本地种子数据。

当前数据库是本地文件，不是云数据库。默认位置为：

```text
data/tickets.db
```

可以通过环境变量覆盖路径：

```text
TICKET_DB_PATH=D:\\data\\hotspot-workbench.db
```

当前没有要求配置 MySQL、云数据库、Redis、RocketMQ、MinIO 或 Qdrant。

## 5. 已知缺口、风险与当前边界

### 5.1 身份与权限缺口

当前没有登录、用户管理、角色管理、会话管理、RBAC 或对象级授权。也就是说，当前版本适合本地单用户演示，不应直接作为多用户生产系统暴露到公网。

下一阶段必须优先补齐：

- 登录和登出；
- 用户、角色和权限模型；
- 后端接口鉴权，而不是只在前端隐藏按钮；
- 对热点、分析结果和审计记录执行对象级权限检查，防止越权访问和 IDOR；
- 审计记录中保存操作者身份、时间、动作和目标对象；
- 未登录、无权限、越权、过期会话的自动化测试。

### 5.2 异步 Agent 能力尚未形成

当前分析接口是同步请求模型，尚未形成独立的 Agent 任务、步骤、重试、取消、进度推送和失败恢复模型。参考图中的 SSE、消息队列和 Agent 工作台能力目前没有完整落地。

推荐先使用 FastAPI 自带能力和 SQLite 状态表完成最小版本：

- `BackgroundTasks` 或进程内任务执行；
- `agent_runs`、`agent_steps` 等任务状态表；
- `StreamingResponse` 或 SSE 推送任务进度；
- 任务状态、错误信息、重试次数和取消标记可查询；
- 仅当出现跨进程、跨机器或高并发需求时，再评估 Redis、RocketMQ 或其他队列。

### 5.3 存储与搜索能力边界

SQLite 当前足以支撑本地演示、小规模单机和业务流程验证，但不适合直接承诺高并发、多实例写入和复杂运营规模。

当前没有：

- MySQL 或其他云数据库部署；
- MinIO 对象存储；
- Qdrant 向量检索；
- 多租户数据隔离；
- 自动备份、迁移和恢复流程。

若后续需要全文检索，优先评估 SQLite FTS5；若后续需要语义检索、Embedding 或 RAG，再引入向量数据库。不要在尚未确认检索需求前直接引入 Qdrant。

### 5.4 多媒体和生产部署边界

当前没有实现 FFmpeg、Tesseract、TeleSpeechASR、MinIO 和 Docker Compose 生产部署。它们应根据真实业务需求逐项加入，而不是作为当前版本的必选完成项。

当前本地部署适合：

- 产品流程验证；
- 单机联调；
- 小规模演示；
- 规则和模型接口试验。

当前不应宣称已经完成：

- 公网多用户部署；
- 高可用；
- 多实例扩展；
- 完整安全审计；
- 生产级备份恢复；
- 生产级消息队列和媒体处理编排。

## 6. 技术路线决策

### 6.1 当前采用

| 层次 | 当前选择 | 当前用途 |
| --- | --- | --- |
| Web | Vue 3、Vite、现有组件体系 | 线索列表、详情、分析和状态操作 |
| API | Python、FastAPI、Pydantic、httpx | REST API、校验、DeepSeek 调用 |
| 数据 | SQLite | 线索、分析、事件和任务状态的本地持久化 |
| AI | 本地规则 + DeepSeek API | 风险初筛、分类和辅助分析 |
| 部署 | Uvicorn 本地服务，后续按需 Docker Compose | 开发和本地验证 |

### 6.2 暂不采用或延后采用

- 不迁移到 Java/Spring Boot；
- 不为了对齐参考图而引入 Undertow、MyBatis-Plus；
- 不提前引入 MySQL、Redis、RocketMQ、Redisson；
- 不提前引入 MinIO、Qdrant；
- 不提前实现 FFmpeg、Tesseract、ASR；
- 不在当前阶段引入 LangChain，仅在需要复杂 Agent 编排且直接 Python 函数不足时重新评估；
- 不配置 hash 验证。
